# Continuous Weekly Threads

These activities run every week across all roadmap phases. They build the habits and evidence expected from a Technical Lead without blocking the main sequence.

## 1. Leadership and Behavioral Journal — 20–30 Minutes

Record one real situation from the current job each week.

### Weekly Entry Template

- **Date and context:**
- **Problem or risk:**
- **My responsibility:**
- **Options considered:**
- **Decision and trade-off:**
- **How I communicated or influenced:**
- **Outcome and measurable impact:**
- **What I would improve:**
- **Possible interview themes:** ownership / conflict / mentoring / ambiguity / incident / delivery / design decision

Over time, convert the strongest entries into concise STAR stories.

## 2. Light Coding Practice — 30–45 Minutes

The goal is consistency and clean reasoning, not high problem volume.

Rotate among:

- One data-structure or algorithm problem
- One Python implementation/refactoring problem
- One API or concurrency exercise
- One low-level design component

For each session, record:

- Problem and pattern
- First approach and complexity
- Edge cases missed
- Final improvement
- One reusable lesson

## 3. Evolving Capstone — 1–1.5 Hours

Extend the same system throughout the roadmap. Every new layer must include a design decision, implementation, test, and production consideration.

See [../Capstone/README.md](../Capstone/README.md).

## Weekly Review — 10–45 Minutes

- What became clearer?
- What remains a Tier A gap?
- What did the capstone prove or expose?
- Which real work event belongs in the leadership journal?
- What is the single most valuable next step?
